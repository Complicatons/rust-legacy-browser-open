# Pilot deployment (private, unverified against a real server)

Three processes, all project-owned. None of them runs or bundles the original game software.

1. **Central service** (one per project): `node tools/central.mjs new-key /etc/rlb-central/keys`, edit `central.example.json`, `node tools/central.mjs check|run <config>`. Put it behind HTTPS (or configure `tls`). It serves the website (`site/`) and the API from one origin. Behind a reverse proxy, list it in `trustedProxies` (`"loopback"` for a proxy on the same host, plus `"cloudflare"` when Cloudflare is in front) so rate limits see each player's address instead of the proxy's (`bridge/client-ip.mjs`); without it every request counts as the proxy. Steam needs the real public URL.
2. **Adapter sidecar** (beside each game server): generate two keys with `openssl rand -hex 32` (plugin key, control key), edit `sidecar.example.json`, `node tools/adapter-sidecar.mjs <config>`. Put the plugin key in the Oxide plugin config (`PluginKeyHex`) and install `adapter/RustLegacyBrowser.cs`; servers without Oxide use the vanilla patch instead (`tools/vanilla-patcher/README.md`). `namespace` stays `null` (linked identities only) until the operator confirms a safe ID range for new browser characters. Set `trustSteamIds` only on servers that verify genuine Steam tickets.
3. **Gateway** (beside each game server): register the server on the website (owner panel), then `node tools/gateway.mjs enrol <config> <code>` within 15 minutes, `check`, `run`. Expose it through HTTPS as `wss://…/play` and publish the server from the owner panel once its heartbeat shows online. Set `trustedProxies` to whatever sits in front of it (`["loopback"]` behind a local HTTPS proxy, `["cloudflare"]` when it serves TLS straight to Cloudflare).

Not yet verified against a real Rust Legacy server: see HANDOFF.md (native integration needs a permitted isolated test host).

**Gateway metrics (optional):** put a random token (`openssl rand -hex 24`) in a file, set `"metricsTokenFile"` in the gateway config, and scrape `GET /metrics` with `Authorization: Bearer <token>` (Prometheus text: open sessions, in-game players, admissions/denials by reason, native approvals/denials/closures, rate-limited commands, heartbeat results). Without the setting `/metrics` is not served; `/healthz` stays public.

**Game page:** `"serveGame": true` makes the central service serve the game at `/play` (files from `browser/` and `browser/assets/recovered/`, which must be exported on that host). The website hands the one-use join ticket to the game through `sessionStorage`, which only works on the same origin, so keep the game on the website's origin. Add the website origin to each gateway's `allowedOrigins`.

## Comparing captures

`tools/compare-captures.mjs` decodes Rust Legacy UDP traffic (Lidgren framing, acks, resends, fragments, uLink headers, connect/approve/deny, clock resync, Create/Destroy, RPCs via `bridge/ulink/rpc-schema.json`, NGC A/C/D via the NGC registry) with our own `bridge/ulink` codecs and re-encodes every decoded message to check it round-trips. It reads pcap and pcapng (Ethernet, Npcap loopback, Linux cooked, raw IP; IPv4/IPv6). The server port defaults to 29015 and is found automatically from the uLink `Connect` if nothing uses it.

- `node tools/compare-captures.mjs decode capture.pcapng [--port 29015|auto] [--peer IP[:PORT]] [--session N] [--json out.json] [--text out.txt] [--all] [--strict]` writes a per-session timeline (time, direction, channel/seq, message, RPC name and decoded arguments). Unknown or undecodable bytes are marked `!!` with hex. `--all` also lists acks and fragments; `--strict` exits 1 when anything failed to decode or round-trip.
- `node tools/compare-captures.mjs compare ours.pcapng native.pcapng [--json report.json] [--text report.txt]` compares our gateway's session with the original client's (P2 reference capture). The report lists client→server messages only one side sends (marked `!!!`), header, channel, timestamp and size differences per message, argument ranges, send intervals (for example the `GetClientMove` rate), Lidgren behaviour (MTU, coalescing, ack delay, resends, pings), and the message order per phase.
- `node tools/compare-captures.mjs record --target 127.0.0.1:29015 --listen 29016 --out gateway.pcapng` relays UDP and records both directions, for when Wireshark is not available. Point the gateway's `native.port` at the listen port. Ctrl+C writes the file.
- `node tools/compare-captures.mjs selftest` records our gateway and a stand-in client against the mock server and compares them.

**Capture settings for the VM.** The server, gateway and native client talk over the guest's loopback, so capture **inside the guest**: install Npcap with "Support loopback traffic" ticked, then capture on *Adapter for loopback traffic capture* with the filter `udp port 29015`. Save as pcapng, export it on the one-way path, and decode it on the host. On the **host**, capture on **VMnet1** (host-only) to watch everything the VM sends; there you will only see the gateway's WebSocket and any blocked outbound attempts, not the uLink UDP. Use separate files for the gateway session and the native-client session so each holds one clean session (or pick one with `--session` or `--peer`). The NGC registry (`browser/assets/recovered/ngc/registry.json`, from `python -I tools/export_ngc_registry.py`) is needed to name NGC calls; pass `--registry` if it lives elsewhere.

## Isolated VM test (vm-test)

Everything for the SERVER-TESTING-PLAN topology lives in `deploy/vm-test/`. Read `deploy/vm-test/RUNBOOK.md` for the steps (VMware host-only VM, phases P0–P9, approvals, exports). In brief:

- **Configs:** `settings.json` (addresses, ports, the recorded server-zip and Assembly-CSharp hashes, the shipped `Run Server.bat` arguments) and `config/*.vm-test.json`. Central runs on the host at `http://192.168.56.1:8080`. The gateway and sidecar run in the VM, and the gateway serves `wss://192.168.56.10:28443/play`. `server/server.cfg` is the shipped cfg with only `rcon.password` replaced. Secrets are generated inside the VM (`scripts/03-New-Secrets.ps1`) or in `%LOCALAPPDATA%\RLB-vm-test` on the host, never in the repo.
- **Gateway exposure:** `"mode": "vm-test"` with `"testHostOnlyBind": {"subnet": "192.168.56.0/24"}`. Only then may the gateway bind a non-loopback address without a production TLS setup. The address must be inside the private host-only subnet and belong to the machine. Public, wildcard and loopback addresses are refused, and a warning banner is printed. Production configs (no `mode`) reject the option (`tests/vm-test-config.test.mjs`). TLS may also be a PFX (`"tls": {"pfx", "passphraseFile"}`), which the VM makes with `New-SelfSignedCertificate`. The host trusts that key only in a dedicated Edge profile (`host/Start-TestBrowser.ps1`).
- **Scripts:** `scripts/*.ps1` run **inside the VM only** and refuse on non-VMware hardware. Each prints its plan and needs `-Apply`; starting `rust_server.exe` also needs `-ConfirmRunOriginalBinaries` and a passing isolation check. `host/*.ps1` cover the host side: central, the firewall rule, the isolation audit and capture analysis, the test browser, read-only export import, and adapter/patcher builds.
- **Tools ISO:** `node tools/build-vm-iso.mjs` uses Windows' built-in IMAPI2FS through `tools/new-iso-image.ps1` and downloads nothing. It packages our gateway/sidecar code and its node_modules, `deploy/vm-test`, the recovered data the gateway needs, the adapter/patcher build outputs (`build/vm-test/adapter`), the hash-verified `RustLegacyServer.zip` and the installers you put in `build/vm-test/installers`. The output is `build/vm-test/rlb-vm-tools.iso`, with `.sha256` and `.contents.txt`. `--handoff <serverId> <code>` makes a small ISO carrying the enrolment code.

## How to run against the VM (gameplay matrix and soak)

Both harnesses run on the **host** only, drive headless Edge (with the in-page Pointer Lock stand-in from `tools/qa-browser.mjs`), and talk only HTTP/WebSocket to host central and the VM gateway. They never start or touch original binaries.

1. In the VM, the server, sidecar and gateway are up (`deploy/vm-test/RUNBOOK.md` P4), and the server is published on the host website. Copy `deploy/native-test.example.json` and set `serverId` (owner page).
2. Create the test accounts on the website (`/register`): one player (e.g. `native-tester`) and, for the soak, `soak-bot-1` … `soak-bot-N` with one shared password.
3. Secrets go in env vars only (the config refuses inline passwords): `RLB_NATIVE_PASSWORD`, `RLB_SOAK_PASSWORD`, `RLB_GATEWAY_METRICS_TOKEN` (from `C:\RLB\secrets\metrics.token`), and `RLB_NATIVE_RCON_PASSWORD` (`03-New-Secrets.ps1 -ShowRcon`) for the admin rows. **A wrong rcon password kicks** (original `rcon.login`); without it the admin rows (`inv.give`, `env.time`, `airdrop.drop`, the foundation, `kick`) are skipped.
4. Check, then run (PowerShell, `$env:REQUIRE_GPU='1'`):
   - `npm run test:native -- --config my-native.json --dry` (validates the config, prints the plan; `--list` shows every row)
   - `npm run test:native -- --config my-native.json [--rows move.*,chat.say,-net.kick]` writes `analysis/native-runs/<time>/results.json`, `results.md`, screenshots and `frames.json` (every gateway frame the page received or sent, secrets redacted). Exit code 1 on any fail/error.
   - `npm run soak:bots -- --config my-native.json --bots 8 --duration 3600 [--behaviours walk,chat,reconnect]` writes `analysis/native-runs/<time>-soak/soak.json` + `soak.md` (per-bot console/chat round trips, drops, reconnects, corrections, page heap, gateway `/metrics` timeline). Ctrl+C stops gracefully and still writes the report.
5. Self-tests without the VM: `npm run test:native -- --mock` and `npm run soak:bots -- --mock --bots 3 --duration 60` (only the Legacy server is mocked; `NATIVE_MOCK_ALL=1` also drives the real-only rows' UI paths).

Rows only meaningful on the real server: `gather.node` (server resource nodes), `build.foundation` (server-created held item and structure), `wildlife.seen`; `airdrop.drop` is only half-modelled by the mock. Manual rows (fall damage, crafting, deployables, combat, raiding, voice, packet loss) are listed as skipped with the reason. Order matters: `death.suicide`, `join.sleeper` and `net.kick` (ends the session) run last.
